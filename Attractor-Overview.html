Attractor is a receipt-first, content-addressed provenance substrate for turning scattered evidence into reviewable knowledge. It is designed for teams, agents, research groups, and operational systems that need to know not just what a claim says, but exactly what source bytes produced it, which projector promoted it, and whether the result can be replayed.

Attractor is best understood as a synthesis of established patterns: content addressing, provenance graphs, tamper-evident append logs, CRDT-style convergence for value sets, and knowledge-graph projection. The construction is opinionated around one principle: generated knowledge should carry its receipts.

Why It Exists

Most knowledge systems preserve final prose better than they preserve evidence. Wikis, issue trackers, chats, documents, logs, tickets, test runs, and review comments all contain useful claims, but they drift apart over time. A cleanup or summary may be correct, stale, duplicated, or unsupported, and normal document tools rarely make that difference falsifiable.

Attractor exists to make the workflow auditable:

  • evidence stays evidence until a typed projector promotes it;
  • identical content-derived values converge instead of multiplying silently;
  • provenance is first-class, not an optional note;
  • receipts make later verification possible;
  • wiki, HTML, graph, and dashboard outputs are projections, not the trust anchor.

Core Model

Attractor has three working layers:

Layer What It Does Closest Prior Art Important Boundary
Convergent value layer Hashes content values so identical values converge to one node. Content-addressed storage, Merkle DAGs, grow-only CRDT sets. CRDT-style applies to the value set only: idempotent and order-independent.
Ordered provenance layer Records each observation as an append-only receipt chain. Event sourcing, tamper-evident logs, Certificate Transparency-style consistency. Not a CRDT: the receipt chain is ordered, single-head, and order-sensitive.
Projection layer Emits reviewable manifests, Markdown, HTML indexes, graph exports, and API snapshots. Knowledge graphs, RDF/provenance models, static-site projection. Generated outputs are read models; reviewed source remains the human editing surface.

The result is a graph where evidence can converge without losing history.

Core Concepts

Concept Meaning In Attractor
Cell / value node A content-addressed unit of evidence or derived data.
Provenance The source page, issue, chat span, ticket, command, file, or run that produced a value.
Projector A typed boundary that turns raw evidence into structured claims and emits a receipt.
Relation A typed edge such as page -> source_issue, claim -> source_span, or page -> duplicate_of.
Receipt A reproducible record of inputs, projector version, output hashes, validation status, and target commit or URL.
Manifest A reviewable output such as an audit file, taxonomy map, duplicate report, or HTML navigation dataset.

Worked Micro-Example

Suppose the same durable claim appears in a ticket comment and a chat archive:

Renamed documentation pages must preserve redirects.

Attractor stores one content-addressed value for that sentence and attaches two provenance entries:

value: blake3("Renamed documentation pages must preserve redirects.")
provenance:
  - ticket #1234 comment A span 10-18
  - chat:#docs msg C span 4-12

A generic graph database might store two rows, or one row with provenance added by application convention. Attractor makes the convergence and provenance behavior part of the contract: one value, complete source multiset.

General Workflow

For a knowledge-base cleanup, research synthesis, compliance evidence set, or incident report, Attractor should begin with a read-only audit manifest:

Field Purpose
artifact Current document, ticket, page, message span, or record.
canonical_path Proposed stable location or identifier after cleanup.
category Proposed top-level category or domain.
source_ref Source issue, ticket, document, dataset, or archive reference.
source_receipt_digest Frozen digest tying the proposal to exact source evidence.
related_refs Rehydratable spans that support claims or context.
topic_aliases[] Reviewed aliases for secondary discovery, with measured yield.
duplicate_of Canonical target when this artifact duplicates another artifact.
missing_summary Source material exists but is not summarized yet.
claim_status Evidence-only, proposed, promoted, rejected, or needs-review.
proposed_action Move, merge, split, summarize, leave alone, or retire.

Only after that manifest is reviewed should projectors move, merge, or publish summaries.

Example: Milton Issue Migration

Milton's issue and wiki migration is a concrete Attractor use case, not the only use case. The batch source can be pinned to a frozen GitHub issue snapshot and a wiki commit, then projected into audit manifests and public pages with readback receipts. That example shows the general pattern:

  1. freeze the source universe;
  2. compute digests for exact source bytes;
  3. project candidate pages, duplicates, and missing summaries;
  4. review the manifest before changing durable documentation;
  5. publish Markdown and HTML with source and projector receipts.

The same pattern applies to any team that needs reproducible knowledge-base cleanup.

Markdown And HTML Projection

Attractor supports human-authored source; it does not replace authorship. A common deployment uses Markdown as the canonical editing surface and HTML as a polished projection.

Output Source Target
Markdown pages Reviewed source Markdown and manifests. Wiki, docs folder, or repository documentation.
Polished HTML Same reviewed source and manifests. Static site such as GitHub Pages.
Audit reports Attractor receipts and projector outputs. PR-reviewed manifests or audit pages.
Graph query views Content-addressed values and relations. API/query surface, not hand-authored prose.

Each render should carry a generated receipt:

Receipt Field Meaning
source_commit Git commit of the source.
source_path Source path.
source_sha256 Hash of the exact source bytes.
projector_version Version or commit of the render projector.
target wiki, pages, manifest, or another declared output target.
target_commit / target_url Where the rendered output landed.

Threat Model

Attractor gives tamper-evident provenance against rewrite, reorder, truncation, or appended forgery given an honest externally persisted head or receipt. It does not prevent a coordinated rewrite of both the chain and the trusted head.

Content addressing proves value identity. It does not prove social truth. Claims become canonical only after their source spans are rehydratable from the snapshot and reviewers promote them.

Relationship To Graph Databases

A graph database is a general query and traversal substrate. Attractor is a convergence and trust substrate. They compose: Attractor can produce a verified graph snapshot that a graph database later indexes for ad-hoc traversal. The receipt and provenance layer comes first; the query layer comes after the evidence layer.

Non-Goals

  • Attractor is not the canonical editor for every document.
  • Attractor is not a free-text scraper that promotes uncited claims.
  • Attractor is not a magic immutable ledger without an honest head.
  • Attractor is not a generic replacement for all graph databases.
  • Attractor should not publish changes blindly; it should emit reviewable manifests and receipts first.

Practical Rule

If a future reviewer cannot answer "what exact bytes produced this claim, through what projector, at what version, with what receipt?" then the claim is not ready to become canonical knowledge.

Related Work

Attractor's components map to known literature:

  • IPFS / Merkle DAGs: content-addressed blocks and links.
  • W3C PROV: entity, activity, and agent provenance.
  • Named graphs and provenance-aware knowledge graphs: graph assertions with source context.
  • CRDTs: convergent value-set behavior.
  • Crosby-Wallach and Certificate Transparency: tamper-evident logs and honest-head threat model.
  • Trusty URIs and nanopublication-style work: verifiable linked artifacts.
  • Agent-memory research: portable, provenance-bearing memory.
