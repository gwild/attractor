Attractor is useful wherever a team needs to convert messy evidence into durable knowledge without losing proof of origin. The starting point is not "let automation rewrite everything." The starting point is a read-only, receipt-backed manifest that reviewers can inspect before anything becomes canonical.

Knowledge-Base Cleanup

Knowledge bases accumulate duplicates, stale pages, orphaned notes, inconsistent titles, and unsupported summaries. Attractor can audit the corpus and propose actions with receipts.

Manifest Field Meaning
artifact Current page, document, ticket, or record.
canonical_path Proposed stable destination after taxonomy cleanup.
category Proposed top-level category.
source_ref Issue, ticket, document, dataset, or discussion that produced durable content.
source_receipt_digest Digest tying the proposal to exact source bytes.
related_refs Source spans that support or explain the artifact.
topic_aliases Reviewed aliases for backfill searches.
duplicate_of Canonical target if this artifact duplicates another.
missing_summary Source material exists but has not been summarized.
claim_status Evidence-only, proposed, promoted, rejected, or needs-review.
proposed_action Move, merge, split, summarize, leave alone, or retire.

Acceptance Bar

A cleanup proposal is ready only when each proposed action can answer:

  • what source bytes support the action;
  • which projector produced the proposal;
  • what commit and source snapshot were used;
  • whether another reviewer independently saw the same relationship;
  • what should happen if the source is later corrected.

Research Synthesis

Research threads often mix papers, notes, quotes, chat summaries, and claims. Attractor keeps those layers separate:

Step Output
Freeze the source set. Snapshot digest and source list.
Extract candidate claims. Evidence-only claim nodes with source spans.
Group claims by topic. Reviewable outline, not final prose.
Promote reviewed summaries. Cited paragraphs with receipt IDs.
Reproject when sources change. Diff of claims, citations, and summaries.

This helps a team write literature reviews or white papers without blurring source evidence into generated interpretation.

Chat And Meeting Backfill

Chat and meeting transcripts contain decisions that never became durable documentation. Attractor can backfill them into candidates without pretending the transcript is already canonical.

Step Output
Select reviewed aliases for a topic. Query plan with expected yield.
Rehydrate messages from archive snapshots. Source spans and message receipts.
Project candidate claims. Evidence-only claim nodes.
Link to existing pages or tickets. Proposed relations.
Human review. Promoted summary or rejected candidate.

The rule is simple: chat can suggest knowledge, but only reviewed projections can promote it.

PR Review And Change Memory

Engineering review often repeats the same reasoning: proof rows must match a head SHA, risk statements must match the diff, platform-specific paths need platform proof, and review conclusions must bind to a specific version. Attractor can remember those patterns as evidence-backed review rules.

Useful outputs:

  • recurring blocker taxonomy;
  • review checklist suggestions bound to changed paths;
  • examples of past failures with source PRs;
  • head-bound review receipt history;
  • "this looks like prior issue X" links.

This should assist reviewers, not auto-approve code.

Incident Forensics

When a service fails, evidence is scattered across alerts, logs, commits, dashboards, and manual commands. Attractor can connect those artifacts into an incident graph.

Artifact Relation
Alert message incident -> first_seen
Command output incident -> diagnostic_receipt
Fix PR or change request incident -> remediation
Post-fix verification remediation -> live_proof
Follow-up ticket incident -> prevention_task

The resulting page can explain what happened without losing the proof trail.

Compliance And Audit Evidence

Compliance programs often need to show not only that a control exists, but when it was checked and what evidence was reviewed. Attractor can bind policy claims to evidence receipts:

  • control statements;
  • source policy text;
  • test or command output;
  • reviewer signoff;
  • exception records;
  • generated audit packets.

The goal is not to replace governance tools. The goal is to make evidence packets reproducible.

Agent Or Assistant Memory

Long-running agent systems need memory that can be inspected. Attractor can store agent memory as source-backed claims rather than opaque embeddings alone.

Examples:

  • "show the latest receipts for this project";
  • "find all pages touched by this cleanup";
  • "which issues mention proof-row staleness?";
  • "which chat decisions produced this rule?";
  • "what source supports this assistant memory item?"

Example: Milton Issue Migration

The Milton issue migration is a concrete demonstration of these general patterns. Issues and comments were frozen, digested, projected into wiki pages, checked by readback, and published with receipts. The use case is specific, but the contract is general: source snapshot plus projector version plus target receipt.

Non-Goals

  • No blind rewriting.
  • No promotion from raw chat without source spans.
  • No claim of truth from content hashes alone.
  • No replacement for human review of summaries.
  • No query database before the evidence contract is working.

Roadmap

Phase Deliverable Gate
1 Read-only audit manifest for a bounded corpus. Manifest reviewed; no writes yet.
2 Duplicate and missing-summary report. Source spans rehydrate from bound snapshots.
3 Reviewed moves and summaries. Redirects or references preserved; receipts attached.
4 HTML and graph projections. Generated from the same source/manifests.
5 Chat, PR, incident, or research backfill. Promotion rules proven on the first corpus.
