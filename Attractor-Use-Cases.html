Attractor Use Cases

Attractor should start narrow: produce reviewable, receipt-backed manifests for Milton’s wiki and issue cleanup work. After that path is proven, the same substrate can support chat backfill, PR-review memory, incident forensics, handoff search, and research synthesis.

First Use Case: Wiki Cleanup

The immediate use case is a read-only audit of the Milton wiki. The goal is not to let an agent rewrite the wiki blindly. The goal is to give reviewers a manifest that says what should move, merge, split, summarize, or retire — with receipts.

Manifest Field Meaning
page Current wiki page path.
canonical_path Proposed stable destination after taxonomy cleanup.
category Proposed top-level category.
source_issue GitHub issue or discussion that produced durable content.
source_receipt_digest Digest tying the proposal to exact source bytes.
related_chat_refs Chat spans that support or explain the page.
topic_aliases Reviewed aliases for backfill searches.
duplicate_of Canonical target if this page duplicates another.
missing_summary Source material exists but has not been summarized.
claim_status Evidence-only, proposed, promoted, rejected, or needs-review.
proposed_action Move, merge, split, summarize, leave alone, or retire.

Acceptance Bar

A wiki cleanup proposal is ready only when each proposed action can answer:

  • what source bytes support the action;
  • which projector produced the proposal;
  • what commit and source snapshot were used;
  • whether another agent independently saw the same relationship;
  • what should happen if the source is later corrected.

Chat Backfill

Team chat contains decisions that never became durable documentation. Attractor can backfill chat into candidates without pretending chat is already canonical.

Step Output
Select reviewed aliases for a topic. Query plan with expected yield.
Rehydrate messages from archive snapshots. Source spans and message receipts.
Project candidate claims. Evidence-only claim nodes.
Link to existing pages/issues. Proposed relations.
Human review. Promoted summary or rejected candidate.

The rule is simple: chat can suggest knowledge, but only reviewed projections can promote it.

PR Review Memory

PR review often repeats the same reasoning: proof rows must match head SHA, predicted impact must match the diff, Windows-native paths differ from WSL, and direct mentions need head-bound review markers. Attractor can remember those patterns as evidence-backed review rules.

Useful outputs:

  • recurring blocker taxonomy;
  • review checklist suggestions bound to changed paths;
  • examples of past failures with source PRs;
  • head-bound review receipt history;
  • “this looks like prior issue X” links.

This should assist reviewers, not auto-approve code.

Incident Forensics

When a service fails, evidence is scattered across chat, logs, commits, dashboards, and manual commands. Attractor can connect those artifacts into an incident graph.

Artifact Relation
Alert message incident -> first_seen
Command output incident -> diagnostic_receipt
Fix PR incident -> remediation
Post-merge verification remediation -> live_proof
Follow-up issue incident -> prevention_task

The resulting page can explain what happened without losing the proof trail.

Agent Handoff And Search

Agent handoff files are local and intentionally small. Attractor can help search durable history around a handoff without turning handoff notes into global state.

Examples:

  • “show the latest receipts for PR #3095”;
  • “find all wiki pages touched by the Attractor cleanup”;
  • “which issues mention proof-row staleness?”;
  • “which chat decisions produced this rule?”

Research Synthesis

Research threads benefit from the same pattern: sources stay separate from claims, summaries carry citations, and generated pages show what evidence supports each section.

Attractor can produce:

  • annotated bibliographies grouped by claim;
  • “core anchors vs analogues” sections;
  • source reliability labels;
  • unsupported-claim reports;
  • update receipts when a source set changes.

Non-Goals

  • No blind wiki rewriting.
  • No promotion from raw chat without source spans.
  • No claim of social truth from content hashes alone.
  • No replacement for human review of summaries.
  • No query database before the evidence contract is working.

Roadmap

Phase Deliverable Merge Gate
1 Wiki audit manifest for existing pages. Manifest reviewed; no page moves yet.
2 Duplicate and missing-summary report. Source spans rehydrate from bound snapshots.
3 Reviewed wiki moves and summaries. Redirects preserved; receipts attached.
4 HTML and graph projections. Generated from same Markdown/manifests.
5 Chat/PR/incident backfill. Promotion rules proven on wiki cleanup first.
