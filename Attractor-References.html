Core Anchors

Attractor Piece Source Supports Boundary Note
Content-addressed value identity Juan Benet, “IPFS - Content Addressed, Versioned, P2P File System,” arXiv:1407.3561 Merkle DAGs, content-addressed blocks, hash-derived identity. Attractor is not IPFS; it borrows content-addressing and DAG vocabulary.
Provenance model W3C PROV-DM, “The PROV Data Model” Entities, activities, agents, and provenance relations. PROV is a model; Attractor adds Milton-specific receipts and projection gates.
Provenance-bearing graph assertions Carroll, Bizer, Hayes, Stickler, “Named Graphs, Provenance and Trust,” WWW 2005 Graph assertions with source context and trust metadata. Named graphs do not by themselves enforce Attractor’s append-only receipt chain.
Tamper-evident logs Crosby and Wallach, “Efficient Data Structures for Tamper-Evident Logging,” USENIX Security 2009 Append-only log integrity, inclusion checks, consistency checks, auditor threat model. The guarantee depends on an honest persisted head or external checkpoint.
Deployed Merkle log pattern RFC 9162, “Certificate Transparency Version 2.0” Signed tree heads, inclusion proofs, consistency proofs. CT is a public certificate-log system; Attractor is a local knowledge substrate.
CRDT-style convergence Shapiro, Preguiça, Baquero, Zawirski, “Conflict-Free Replicated Data Types,” SSS 2011 Idempotent, commutative, order-independent convergence for value sets. Applies only to Attractor’s value-set layer; the provenance chain is ordered and not a CRDT.
Event log and projections Martin Fowler, “Event Sourcing”; Microsoft Azure Architecture Center, “Event Sourcing pattern” Append-only event history and derived read models/projections. Event sourcing does not imply content addressing or source-span receipts.
Verifiable linked artifacts Kuhn and Dumontier, “Trusty URIs: Verifiable, Immutable, and Permanent Digital Artifacts for Linked Data,” ESWC 2014 Hash-bound identifiers for verifiable artifacts. Trusty URIs identify artifacts; Attractor also manages promotion, review, and receipts.

Design Analogues

Area Sources To Track Why It Matters
Nanopublications Nanopublication literature and tooling. Small citable assertions with provenance and publication metadata resemble Attractor claim nodes.
Whyis / provenance-supported knowledge graphs Whyis knowledge-graph framework papers and docs. Shows practical provenance-aware knowledge graph workflows.
Agent memory graphs A-MEM, Portable Agent Memory, Graphiti-style temporal/episodic KG systems. Useful analogues for linked agent memory, but not the foundation unless verified against the deployed design.
Knowledge graph traceability Full-traceability and provenance work for knowledge graphs. Helps explain update history, source lineage, and auditability.
Static-site projection GitHub Pages, Jekyll, Mermaid-aware renderers. Supports the two-projector model: wiki Markdown and polished generated HTML from the same source.

“Attractor supports citable knowledge artifacts.” Trusty URIs, nanopublications, Whyis.

Boundary Language For The Wiki

Use this phrasing when explaining novelty:

Attractor is a Milton-specific composition of established patterns: content-addressed values, provenance-bearing graph assertions, an append-only tamper-evident receipt log, CRDT-style convergence for the value set, and generated projections for wiki/HTML/query surfaces.

Avoid these overclaims:

  • “Attractor invented content-addressed storage.”
  • “Attractor is a CRDT.”
  • “Attractor is a blockchain.”
  • “Attractor proves truth.”
  • “Attractor replaces graph databases.”
